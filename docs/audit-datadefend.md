**No code was copied.** This service is written fresh, in its own shape
(a container with an API key, not a Cloudflare Worker with OAuth). What it
took are rules, listed below; MIT asks for the notice only where code is
copied or adapted, so `LICENSE` here is Kaperkunde's alone. If code from
that repository is ever adapted, its notice goes into `LICENSE` beside ours.

## Not taken, and why

| Theirs                                                                                                                                                                                                                                                                                                                                                                        | Why not here                                                                                                                                                                                                                                                                                                                                                                 |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **OAuth only, token in memory, authorise again after every restart**                                                                                                                                                                                                                                                                                                          | Unusable for an always-on service (the reason for issue #142). Here: the owner's API key from PCP's secret, and the installation, device and session kept in the volume and renewed unattended (`src/bunq.ts`).                                                                                                                                                              |
| **No local persistence** (their finding N1: the OAuth token never reaches disk)                                                                                                                                                                                                                                                                                               | A service that renews its own session must keep its installation token and key pair. They live in a named volume, readable by the service's user only; the API key itself is never written there, only a hash of it.                                                                                                                                                         |
| **Loopback bind** (`127.0.0.1` enforced in `vite.config.ts`)                                                                                                                                                                                                                                                                                                                  | Inside a container that would make the published port unreachable. PCP publishes the port on the SSH server's 127.0.0.1 and reaches it through the SSH connection; the server binds 0.0.0.0 inside its own network namespace. In its place: a bearer token PCP sends (`MCP_AUTH_TOKEN`, required by the definition), and Host and Origin checks against DNS rebinding.       |
| **Cloudflare Workers tooling** (wrangler, vite, `agents`, `@cloudflare/workers-oauth-provider`, hono; `npx vite` spawned with `shell: true` from `bin/run.js`)                                                                                                                                                                                                                | A large tree for a local server, and a child process with a shell. Here: two runtime dependencies (`@modelcontextprotocol/server`, `zod`), plain `node:http`, no child process.                                                                                                                                                                                              |
| **A new installation and device registration on every start** (`BunqContext.initialize` has no saved state)                                                                                                                                                                                                                                                                   | bunq allows as few as ten installations a day and lists each device in the app. Here they are made once and reused; a new API key registers a new device on the same installation.                                                                                                                                                                                           |
| **`permitted_ips: ["*"]` on every device**                                                                                                                                                                                                                                                                                                                                    | That needs a wildcard API key and lets the key work from any address. Here the device is tied to the address it is first used from unless the owner asks for more (`BUNQ_PERMITTED_IPS`).                                                                                                                                                                                    |
| **Every request signed** (`X-Bunq-Client-Signature`)                                                                                                                                                                                                                                                                                                                          | bunq requires a signature only to start a session and to create payments. Here: the session start and the draft are signed, reads are not.                                                                                                                                                                                                                                   |
| **A singleton client shared by every MCP connection** (`getBunqClient`, replaced by whoever signed in last)                                                                                                                                                                                                                                                                   | One service instance is one bunq user here (one API key), so there is nothing to mix up; the MCP side is stateless per request.                                                                                                                                                                                                                                              |
| **The OAuth `state` round-tripped unsigned** (`OAuthHandler` `/callback` decodes `atob(state)` and trusts it; only the approval cookie is signed)                                                                                                                                                                                                                             | No OAuth here.                                                                                                                                                                                                                                                                                                                                                               |
| **bunq's error bodies in logs and answers.** `makeSignedRequest` throws `Bunq API request failed: ${await response.text()}`; `getTransactions`, `bunqAccounts`, `getRequestInquiries`, `getTopCounterparties` and `getPaymentAutoAllocates` then `console.error(error)`, and `OAuthHandler` logs bootstrap errors whole, so an error body does reach the log despite claim N7 | Here an error answer is reduced to bunq's `error_description` (at most 300 characters) for the assistant, and the log gets only the status.                                                                                                                                                                                                                                  |
| **Reads limited to accounts (bank accounts only, `monetary-account-bank`), the latest 200 payments, request inquiries, auto-allocates, top counterparties**                                                                                                                                                                                                                   | Issue #142 asks for more: payments with date, amount and counterparty filters and paging, one payment, requests sent and received, scheduled payments, masked cards, minimal user info; and all account kinds (savings, joint). Auto-allocates and "top counterparties" are left out: the owner did not ask for them, and the second is a list of the people the owner pays. |
| **Whole bunq objects passed on** (`getRequestInquiries` returns the inquiry as bunq sends it; `getPaymentAutoAllocates` passes `payment: any`)                                                                                                                                                                                                                                | Here every answer is a view of picked fields (`src/views.ts`): no geolocation, avatars, addresses, document numbers, a card's CVC or PIN assignments.                                                                                                                                                                                                                        |
| **No output schemas, camelCase arguments, no annotations** (`server.tool(name, description, parameters, handler)`)                                                                                                                                                                                                                                                            | PCP reads a tool with no annotations as destructive. Here every tool states all four hints, takes closed snake_case inputs with every property described, and declares its output schema.                                                                                                                                                                                    |
| **Disclaimer and no-support notice**                                                                                                                                                                                                                                                                                                                                          | Kaperkunde keeps this one; the README says what it does and does not do.                                                                                                                                                                                                                                                                                                     |

## Network, in their code

Their server reaches `https://api.bunq.com/v1` (bootstrap and requests),
`https://api.oauth.bunq.com/v1/token` (OAuth code exchange) and redirects
the browser to `https://oauth.bunq.com/auth`; the approval page shows a logo
from `https://bunq.com/assets/img/bunq-logo.svg` (fetched by the browser).
`wrangler.jsonc` turns Cloudflare observability on and declares an `ai`
binding, which matter only if it is deployed, which its README says not to
do. Hosts are string literals at each `fetch`, with nothing that stops a new
one being added.

Here: one host (`api.bunq.com`, or `public-api.sandbox.bunq.com` with
`BUNQ_ENVIRONMENT=sandbox`), fixed in `src/egress.ts` when the transport is
made; requests carry a path, never a URL; ESLint and
`test/egress.test.ts` keep `node:https`, `node:net`, `node:tls` and
`fetch` out of every other module.
